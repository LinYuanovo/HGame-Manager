## 已修复的审阅发现

1. **P2：同路径重新刮削后封面仍显示旧图。** 列表改用 `FileImage` 后，Flutter 不会自动感知文件覆盖；同一图片组件也会继续订阅原图。真实 EXE 中，新文件已为 1600×1000，解码仍得到旧图的 2400×1600。现在共享下载器在成功写入（含 429 重试）后失效文件缓存，`ScrapeApplyService` 在临时图发布到最终路径后再次失效最终路径缓存，列表以图片路径及数据库图片记录 ID 更新组件。快速刮削、重新刮削、刮削中心共用发布逻辑；Steam/DLsite 单个和批量添加共用下载器。回归验证直接检查仍可见的列表 `RawImage`，确认实际渲染已更新且原分辨率不变。
2. **P2：WebDAV 完整 gzip 响应被误报为下载不完整。** 原实现将 HTTP 自动解压后的字节数与压缩后的 `Content-Length` 比较。真实 EXE 使用本地 gzip 响应复现失败。现在关闭底层自动解压，先统计传输字节、再按 gzip 流式解压写入暂存文件；传输长度匹配且流完整结束后才替换目标。普通及 gzip 的成功和中断场景均通过，中断时原备份保留、暂存目录清除。
