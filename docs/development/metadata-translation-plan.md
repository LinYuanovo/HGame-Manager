# 刮削元信息自动翻译实施计划

更新日期：2026-11-10

## 目标与验收

- 在 `codex/metadata-translation` 分支和独立工作树开发。
- 设置中可启用刮削后自动翻译，目标语言为简体中文，支持免密钥 Google 翻译及 OpenAI 兼容的 Chat Completions 接口。
- 翻译标题、简介、特点、更新日志及标签；保留版本、链接、厂商等标识信息。富文本保留布局及图片引用。
- 保存刮削原文，详情页可切换查看原文和译文，切换不触发网络请求。
- LLM 失败时提示用户并尝试 Google；Google 也失败时提示用户，保留原文并正常完成刮削。
- 快速刮削、重新刮削、刮削中心、Steam/DLsite 单个导入及批量导入采用同一翻译处理层。
- 新增 UI 使用 `AppTheme`、`GlassConstants` 和现有组件的设计令牌。

## 执行步骤

1. 核对元数据存储和五个入口 → 验证：列出调用位置及持久化策略。
2. 实现翻译设置、适配器和降级处理 → 验证：成功、超时、错误响应、格式错误、长文本和原文保留测试。
3. 接入共享刮削流程及导入流程 → 验证：五个入口的译文、原文和提示行为一致。
4. 实现设置 UI 和详情原文切换 → 验证：浅色/深色主题、交互、重新加载后原文可用。
5. 串行执行定向测试、静态检查和 Windows 原生集成测试 → 验证：真实文件/数据库读写、真实 Google 请求、LLM 协议及降级链路。
6. 更新交接结果，清理临时样本、一次性测试脚本、日志和截图 → 验证：Git 差异及清理清单。

## 实施约定

- 自动翻译默认关闭，用户启用后生效；LLM 地址、模型和可选密钥由用户配置，密钥不写入日志或游戏元数据。
- Google 使用免密钥网络接口，可能受网络和限流影响；所有错误必须有可见反馈。
- 原文随游戏元数据保存，优先复用既有 JSON 存储，避免不必要的数据库迁移。
- 真实外部 LLM 验证依赖可用接口；没有授权的凭据时验证本地真实 HTTP 协议，明确记录验证边界。
- 验收后清理本次新增的测试源文件、测试样本、日志和截图，验证结果保留在交接文档。
- 不改变版本号，不推送远程；保留任务分支与工作树供审阅。
