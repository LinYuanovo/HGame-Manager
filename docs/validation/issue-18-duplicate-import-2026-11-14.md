## 问题与行为

Issue 所述版本在重复插入时触发 `games.path` 唯一约束。指定基准的 `insertGame` 使用 `ConflictAlgorithm.replace`，还有替换旧记录及其关联的风险；扫描和导入入口仍按路径原始字符串匹配。

- 统一使用 Windows 路径比较键，处理大小写、正反斜杠、末尾分隔符及 `.` / `..`。比较键只用于查重，不修改数据库中的原路径。
- 单个添加在搜索或导入前提示「该游戏已在库中，已跳过」；不刮削、Steam、DLsite 共用相同检查。
- 批量添加先检查数据库及本批次路径，重复项不进入刮削队列；完成结果分别显示成功、跳过、失败数量。
- 仓库插入在 SQLite 事务内重新检查路径，重复时抛出可读的业务异常；其他新游戏可继续导入。已有记录的 ID、收藏、评分、游玩信息、标签和图片关联保留。
- 扫描刷新使用相同比较键匹配旧记录，并在写库事务内复查快照之后新增的目录；重复项跳过，日志记录完成数量及写库失败路径。
- 快速刮削、重新刮削、刮削中心继续通过原共享刮削管线更新已有游戏；新导入后的翻译和目录整理仍复用共享服务。
