# 翻译持久化修复与自定义 Prompt

日期：2026-11-10。工作分支：`codex/integration-ui-translation`，修改基线：`15e141a`。

## 行为变化

- 图片、视频标记保护到完整行内路径末尾，支持制作组或分类名称含方括号的目录；媒体路径不进入翻译请求。
- Markdown 普通链接的显示文字进入翻译，链接目标、图片引用和代码继续保持原值；包含括号的链接目标有回归覆盖。
- 译文字段与标签关系使用同一 SQLite 事务。先准备临时文件，在事务内完成字段及标签写入后替换元数据文件；文件操作失败撤销数据库修改，事务失败恢复此前的元数据文件。
- 元数据已经保存译文快照时，共享方法可直接补齐数据库字段和标签，无需重新请求翻译。
- 通关元数据备份增加 `metadata`，包含译文富文本、原文和图片引用。源文件存在时优先保存源文件；删除后刷新备份继续保留既有快照。详情页在源文件缺失时读取通关备份，旧格式备份仍可正常读取。
- LLM 设置增加多行「翻译 Prompt」输入框。空值显示并使用统一默认提示词，自定义值保存到设置；测试连接与实际翻译采用同一配置。JSON 返回结构及条目顺序约束由共享请求层补充，Prompt 不写入游戏元数据。

## 共享入口

快速刮削、重新刮削、刮削中心继续通过 `applyScrapeResult → translateGameMetadata`；Steam/DLsite 单个及批量导入继续通过各自的导入后处理调用同一个 `translateGameMetadata`。媒体保护、链接文字翻译和 Prompt 均在 `MetadataTranslationService` 生效。

事务复用现有 `syncTags`，通过 `DatabaseExecutor` 参数将字段、标签查询和标签写入绑定到当前事务，避免在事务回调内访问外层连接。测试注入独立数据库，表结构由生产初始化方法创建。
