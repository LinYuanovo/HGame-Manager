### 日志与诊断

`AppLogger` 每条同步刷盘改为有界队列，每 250ms 异步批量写入，错误主动触发刷新，主窗口及浮窗关闭前等待刷新。保留约三天，单个日志达到约 2MiB 后轮转两个旧文件；队列限制约 256K 字符，拥塞丢弃计数可见，单条超长内容截断。

日志携带时间、等级、模块、会话、应用版本、Windows 版本和启动耗时。路径仍优先使用 exe 同级 `logs`，不可写时回退 `%LOCALAPPDATA%\HGame-Manager\logs`。攻略浮窗使用独立文件，避免两个引擎轮转同一文件。

| 链路 | 新增或补强的记录 |
| --- | --- |
| 启动、字体、窗口、首帧 | 阶段完成、耗时、内存快照、异常堆栈 |
| 数据库与旧数据升级 | 打开/升级开始与完成、失败原因；初始化失败可重试 |
| 设置加载/保存 | 读取失败、损坏设置恢复备份、写入失败 |
| 页面与详情 | 页面切换、详情游戏 ID、设置打开 |
| 扫描、刮削共享层、目录整理 | 解析失败、结果应用开始/完成、耗时、元数据写入及整理失败 |
| 存档、WebDAV、导入界面 | 成功/失败、HTTP 状态、传输字节及异常堆栈 |
| HTTP 与更新 | 请求状态、重试次数、耗时、网络或更新解析失败 |
| 攻略浮窗 | 创建/快捷键异常、窗口状态读写、引擎异常、关闭 |

「设置 → 关于 → 诊断日志 → 导出诊断包」生成 ZIP。后台 isolate 处理压缩，最多选最近 9 个日志、每个读取末尾 2MiB。写入和导出会过滤身份认证字段、网址认证信息和查询参数，并将用户目录替换为占位符。WebDAV 失败日志不再写响应正文。诊断包仍可能包含游戏路径等个人信息，界面和 FAQ 已提示分享前检查。

### 复用与性能

- 单条游戏和批量游戏关系加载共用备份图片回退，去掉两套重复逻辑。修复 30 秒路径缓存把尚未查询的其他目录直接当作不存在的错误；普通游戏无需为此逐个查询目录存在性。
- 移除自建 `ImagePreloader`，封面在可见项中用 `Image.file` 和 768px 解码宽度，复用 Flutter 缓存。关闭详情后逐张失效该游戏的封面缓存，保持更新可见。
- 通关卡片构建中的同步目录枚举、metadata 读取改为异步查询并按列表数据缓存；业务操作仍重新确认目录状态。
- 扫描每解析 8 个目录触发多组数据重查，改为扫描结束后一次通知；进度回调保持更新。
- 两种 WebDAV 备份上传复用已有流式上传实现，不再先读取整份备份为内存字节数组。
- 合并主窗口两个平台分支重复的字体加载，修复字体改变后深色主题缓存未失效的问题。
- 数据库初始化失败释放缓存 Future；路径重写失败关闭已打开连接，后续可以重试。

### 原生浮窗检查发现的问题

首次打开攻略浮窗时，`windowManager.center()` 需要 `screen_retriever`，但子引擎原先未注册该插件。真实 Release 日志记录了 `MissingPluginException`。现在仅增加屏幕信息插件注册；版本由主窗口参数传给子窗口。

关闭浮窗的消息处理原先等待窗口销毁后再回复，调用方可能一直等待。现在先回复消息，再异步执行保存状态、刷新日志及系统关闭。浅深色两轮真实窗口创建、置顶、滚动、关闭与主窗口存活验证通过。
